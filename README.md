# Community Waste Reporting

A React + Supabase web app for community incident/waste reporting with role-based dashboards for citizens, coordinators, and agencies.

## Features

- **Citizen flow**: sign up/login, submit incident reports with image + geo location, track personal history.
- **Coordinator flow**: monitor incidents, analytics, map view, notifications, exports, and resource management.
- **Agency flow**: operational response dashboard for dispatch/on-scene/resolution workflows.
- **Map + geolocation**: browser geolocation + OpenStreetMap Nominatim reverse geocoding.
- **Gamification**: citizen points, levels, leaderboard, and citizen activity tracking.
- **Supabase backend**: auth, Postgres tables/views/triggers, storage bucket, and realtime subscriptions.

## Tech Stack

- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS 4
- **UI**: Radix UI + shadcn/ui-style component set, Lucide icons, Recharts
- **Backend (BaaS)**: Supabase (Auth, Postgres, Storage, Realtime)
- **Maps/Location**: Leaflet / react-leaflet, browser Geolocation API, Nominatim
- **Exports**: jsPDF, jsPDF AutoTable, CSV utilities

## Project Structure

```text
/src
  App.tsx                         # Role-based screen switcher
  /components                      # Login + dashboards + analytics + map UI
  /components/dashboard-views      # Citizen/coordinator view modules
  /components/ui                   # Reusable UI primitives
  /db                              # Supabase data-access modules
  /utils                           # Location, zone mapping, export, sample data
  /supabase                        # SQL schema/fix scripts and function scaffolds
  /types                           # Shared TS domain models
/supabase/migrations               # DB migration scripts (reports -> incidents)
```

## Application Architecture

- `src/main.tsx` mounts `App.tsx`.
- `App.tsx` controls role/screen state (`role-selection`, login screens, and 3 dashboards).
- Data operations are centralized in `src/db/*` (incidents, admin, analytics, citizens, notifications, resources, auth, stats).
- Supabase client + typed database contract live in `src/utils/supabase/client.ts`.

## Database & Supabase Setup

This repository contains both **base schema scripts** and **migration scripts** from older `reports` naming to current `incidents` naming.

Recommended order for a fresh setup:

1. Apply base schema (`src/supabase/schema.sql`) if starting from scratch.
2. Apply crisis migration (`supabase/migrations/01_crisis_conversion.sql`) to move `reports` -> `incidents` and add `resources`.
3. Apply citizen/gamification schema (`src/supabase/citizen_schema.sql`).
4. If needed, apply targeted fix scripts in `src/supabase/` (`fix_signup_trigger.sql`, `fix_citizen_trigger.sql`, `fix_notifications_rls.sql`).

> Note: `src/schema.sql` reflects an evolved/current schema snapshot centered on `incidents`.
